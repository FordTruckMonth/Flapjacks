# Security and evidence handling

This is an experimental, read-only investigation aid, not a validated forensic acquisition suite. Live tenant use requires separate authorization, least-privilege roles and operator authentication. Protect local evidence using your organization's approved storage and access controls.

Never post real cases, tenant identifiers, personal data, tokens, passwords, raw logs or screenshots containing evidence in issues or pull requests. The .gitignore helps prevent accidental commits but is not a security boundary.

For vulnerabilities, contact a maintainer privately through an established channel. Do not disclose exploitable details or sensitive evidence in a public issue. Do not assume GitHub private vulnerability reporting is enabled. Use a synthetic reproduction when possible.

If a secret is accidentally published, revoke or rotate it immediately; deleting the current file alone does not remove it from Git history or copies.

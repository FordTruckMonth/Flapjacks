# Flapjacks — organization-wide Microsoft 365 posture audit

![Flapjacks: pixel-art pancakes beside a security audit checklist.](docs/assets/flapjacks-banner.png)

Flapjacks is a read-only, tenant-level Microsoft 365 posture-review tool. The [first-stage Microsoft/NIST mapping](terminal/docs/POSTURE-MAPPING.md) makes evidence boundaries and unassessed areas explicit; it is not a compliance certification.

## Start with the organization-wide audit

Live mode reviews configuration in an authorized Microsoft 365 tenant using approved Microsoft sessions and the read permissions required for each source. Missing or denied sources appear as coverage gaps.

Synthetic mode runs locally with invented evidence. It needs no Microsoft account or tenant connection and makes no assessment of your organization.

The **[PowerShell-only terminal application](terminal/README.md)** is the primary interface for organization configuration review and local posture reports. It also retains the separately scoped target-mailbox log collector described below. No localhost, local web server, HTML UI or automatic browser launch.

```powershell
# Start the live terminal from this repository directory (PowerShell 7.4+)
./terminal/Start-Flapjacks.ps1
# Offline demonstration without any account or Microsoft modules:
./terminal/Start-Flapjacks.ps1 -Mode Synthetic
```

Live startup offers Microsoft Graph device sign-in (default), Exchange device sign-in, or reuse of either session. It derives the tenant and operator from authenticated metadata for confirmation; no tenant GUID is requested up front. **Device-code approval still requires a Microsoft web page on an approved browser/device**; the application itself stays in the terminal and never asks for a password. It does not approve consent or bypass Conditional Access. Optional startup A displays already-approved Audit read scopes and uses one device sign-in, then one AUDIT authorization. Default G is identity-only User.Read; missing capabilities remain gaps, not repeated consent prompts.

- **Audit:** one typed `AUDIT` authorization after displaying verified tenant and concrete organization-wide scope; 46 supported configuration sources. Gaps remain visible, not a security grade.
- **Workbook posture (W):** an explicit opt-in to additional identity, Exchange, and collaboration evidence. Type `WORKBOOK` after checking the displayed tenant; the tool uses already-approved sessions and never requests new permissions. W compares stored mail policies with Microsoft Standard recommendations. See the [workbook posture scope and access matrix](docs/WORKBOOK-POSTURE.md) and [mail-policy controls](docs/MAIL-BASELINE.md).
- **View:** safe, paginated terminal inspection of in-memory evidence. Menu S optionally saves existing results as local JSON; no HTML report is generated by this entrypoint.

Run `./terminal/tests/Test-All.ps1` for the integrated synthetic suite. See [migration and limitations](docs/TERMINAL-MIGRATION.md), [authentication](terminal/docs/AUTHENTICATION.md), and the [historical terminal validation record](terminal/docs/VALIDATION.json). The expanded workbook sources have not been exercised against a live tenant; an offline pass is not live qualification.

### Historical logs for selected mailboxes

**Pull Logs** collects historical activity for up to 50 exact usernames or email addresses. After you confirm the dates and targets, it queries each mailbox separately. It retrieves no message bodies or attachments and has no tenant-wide UAL or directory-audit fallback. The legacy investigator below has its own entry point.

## Five-check posture pilot and optional Posture Report export

This candidate adds a **bounded configuration-review pilot**, not a complete tenant assessment, Microsoft Secure Score calculation, NIST certification or proof of effective protection. The wider Audit still collects up to 46 supported sources; only the five settings below are pilot checks. A matching setting means only that the observed value matches the stated pilot expectation. Organization-specific exceptions need human review, not automatic remediation.

| Pilot check | Read-only source / expected value | Interpretation limits | Project-authored CSF 2.0 association |
|---|---|---|---|
| `EXO-AUDIT`: Organization mailbox auditing | `Get-OrganizationConfig`: `AuditDisabled = false` | Organization default only. Mailbox audit operations, bypass users, license-dependent events, retention and actual event availability are not verified. [Microsoft mailbox auditing](https://learn.microsoft.com/en-us/purview/audit-mailboxes) | PR.PS-04: logging availability |
| `EXO-DIRECT-SEND`: Reject Direct Send | `Get-OrganizationConfig`: `RejectDirectSend = true` | Blocks anonymous accepted-domain envelope senders not attributed to a connector; not all spoofing, and not the visible From header. Legitimate devices/services and connectors need review. This property belongs to OrganizationConfig, not TransportConfig. [Microsoft Exchange guidance](https://techcommunity.microsoft.com/blog/exchange/reject-direct-send-now-generally-available-in-exchange-online/4573787) | PR.PS-01: configuration management |
| `EXO-SMTP-AUTH`: Organization SMTP AUTH default | `Get-TransportConfig`: `SmtpClientAuthenticationDisabled = true` | Per-mailbox settings can override this default. Security defaults and authentication policies also matter. SMTP AUTH supports OAuth as well as basic authentication; this flag is not a complete legacy-authentication or MFA verdict. [Microsoft SMTP AUTH guidance](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/authenticated-client-smtp-submission) | PR.AA-03: authentication |
| `ENTRA-APP-REG`: Default user application registration | Graph `GET /policies/authorizationPolicy`: `defaultUserRolePermissions.allowedToCreateApps = false` | A restrictive pilot baseline, not a universal Microsoft mandate. It concerns the default user role, not privileged-role assignments, existing apps, OAuth grants or consent policy. [Microsoft field definition](https://learn.microsoft.com/en-us/graph/api/resources/defaultuserrolepermissions?view=graph-rest-1.0) | PR.AA-05: access authorizations |
| `EOP-FILE-FILTER`: Common attachments filter | `Get-MalwareFilterPolicy`: `EnableFileFilter = true` for each assessed policy | Setting-level review only: recipient targeting, policy precedence/exceptions, file-type list and action still need review. This does not prove every recipient or malicious attachment is blocked. [Microsoft filter definition](https://learn.microsoft.com/en-us/powershell/module/exchangepowershell/set-malwarefilterpolicy?view=exchange-ps) | PR.PS-01: configuration management |

These are Flapjacks-authored associations with [NIST CSF 2.0 outcomes](https://csrc.nist.gov/Projects/cybersecurity-framework/filters), not an official NIST crosswalk or an assessment that an entire outcome is achieved. CSF is outcome-oriented rather than a prescribed Microsoft settings checklist. No organizational risk/compliance percentage is inferred from five booleans.

### Who obtains the evidence and what access is needed?

An authorized operator obtains tenant data through the normal, explicitly confirmed Audit using separately approved delegated sessions. The exporter only reads that completed in-memory result or an existing audit JSON; it does not sign in, query a provider again, obtain consent, change settings or elevate access. Offline synthetic examples need no tenant access. For a saved file, its producer/operator is responsible for authorized collection and provenance; exporting a file does not authenticate it as a Microsoft response.

The registration check requires the read scope [`Policy.Read.All`](https://learn.microsoft.com/en-us/graph/api/authorizationpolicy-get?view=graph-rest-1.0); it does not require a write scope. Exchange checks need existing RBAC for their exact `Get-*` commands and fields. Licensing, module/platform compatibility, session binding and RBAC remain the separate requirements described below. A denied request is not proof of an unlicensed feature, and a returned policy is not proof of every user's license or effective coverage. No additional administrator role, consent or subscription is granted by this pilot.

Profile `Flapjacks pilot 0.1` uses the exact result labels **Meets selected setting**, **Needs action**, **Not assessed** and **N/A**. N/A requires an explicit documented applicability decision; it is never inferred from missing access or zero records. Missing, null, malformed, partial, denied and unavailable evidence cannot become a passing check. `Collected` with zero rows means a completed collection returned no objects, not a secure configuration; failed access with zero rows remains a gap. Findings retain source status and scope. The separate [workbook posture profile](docs/WORKBOOK-POSTURE.md) adds optional checks; effective MFA enforcement, mailbox overrides and numerous other tenant capabilities remain outside automated assessment.

### Export the existing result, only when requested

After Audit or Workbook posture, terminal **P** saves a Posture Report bundle from the latest Audit result; **S** retains its existing JSON-save behavior. Choose a new private output directory; Enter at the P destination prompt cancels. Export does not recollect. From PowerShell, the equivalent saved-file path is:

```powershell
Import-Module ./terminal/Audit/M365SecurityAudit.psm1
Export-FlapjacksPostureBundle -InputJson '/path/to/audit.json' -OutputDirectory '/path/to/new-private-review'
# Or use the completed Audit result already in this process:
Export-FlapjacksPostureBundle -Result $result -OutputDirectory '/path/to/another-new-private-review'
```

The bundle contains `Posture-Report.pdf` (control table and a separate coverage section), `Posture-Report.xlsx` (control and coverage tabs), and `Posture-Report.csv` (control table). It also retains `checks.csv/json`, `coverage.csv`, `inventory.csv`, `observations.csv`, `audit.json`, `collection-plan.json`, `evidence/*.json`, and one `manifest.json`. Evidence is the selected payload that Flapjacks saved, not original network bytes. Workbook posture does not collect sign-in events, Unified Audit Log events, message trace or mailbox activity; use separately authorized workflows for activity logs. Existing destinations must not be overwritten. Synthetic results remain explicitly synthetic; access failures and incomplete sources remain visible. The default terminal workflow still saves nothing until requested.

**Treat the whole bundle as sensitive internal evidence, not a redacted public report.** Inventory/raw JSON can contain tenant policy identities, addresses, targeting and infrastructure details even without message bodies or credentials. Keep it on approved local storage; review before any separate sharing. Spreadsheet formula-leading text must remain neutralized in CSV, and report text must remain inert. Hashes demonstrate file consistency, not source authenticity, completeness or effective security. No live-tenant validation or production-readiness claim follows from an offline export test.

## Prerequisites and installation

- **PowerShell 7.4+**; use a currently supported stable/LTS release. Windows PowerShell 5.1 and Python are not toolkit prerequisites.
- **Microsoft.Graph.Authentication** for Graph; explicitly opt in to **ExchangeOnlineManagement 3.7+** and its dependencies for Exchange. EXO 3.10+ requires PowerShell 7.6+.
- Start from a clean machine with the official **Windows, macOS or Debian** runtime instructions, then the shared per-user module installer in [Prerequisites and setup](terminal/docs/PREREQUISITES.md). It is a two-step setup, not a runtime bootstrap script.

```powershell
./terminal/Install-Prerequisites.ps1                         # Local plan only
./terminal/Install-Prerequisites.ps1 -Mode Install -IncludeExchange -WhatIf
./terminal/Install-Prerequisites.ps1 -Mode Install -IncludeExchange
```

No automatic elevation, trust/execution-policy change, sign-in or consent. Debian Exchange support is not claimed and its Exchange install is skipped; Purview is unavailable on macOS/Linux. Missing components remain explicit coverage gaps. Synthetic mode needs only PowerShell. See the setup guide before installing.

## Permissions and access requirements

**Synthetic mode needs no Microsoft account, Graph consent, tenant role or Microsoft module.** Live mode requires separately authorized access for the selected workflow. Installing modules, having a license, signing in, receiving Graph scopes, and holding workload roles are different requirements. This section describes the terminal launcher; the preserved legacy workflow below has broader collection boundaries.

### Microsoft Graph: identity is not Audit access

Use a delegated work/school operator in the Microsoft **Global** cloud. Personal Microsoft accounts, app-only authentication and other clouds are unsupported by this workflow. Startup **G** requests only `User.Read` for identity; it does not authorize configuration collection. Startup **A** explicitly requests this current combined Audit read-scope plan, shown before sign-in:

| Delegated scope | Used by the current Audit plan |
|---|---|
| `Policy.Read.All` | Conditional Access, named locations, security defaults, authentication-method/strength policies and other identity policies |
| `Policy.Read.PermissionGrant` | Consent permission-grant policy definitions, not existing application grants |
| `RoleManagement.Read.Directory` | Directory role definitions, assignments and eligibility-instance reads |
| `Domain.Read.All` | Tenant domain inventory |
| `LicenseAssignment.Read.All` | Tenant subscription/SKU inventory, not proof of per-user licensing |
| `DeviceManagementConfiguration.Read.All` | Intune compliance/configuration policy metadata; the permission itself is broader than the fields collected |

The combined plan uses `Policy.Read.All` rather than also requesting `Policy.Read.AuthenticationMethod`, and `RoleManagement.Read.Directory` rather than also requesting `RoleEligibilitySchedule.Read.Directory`. These are the application's configured scopes, not a claim that every API requires all six. See the [exact source catalog](terminal/Audit/docs/SOURCES.md) and [permission plan](terminal/Audit/docs/PERMISSIONS.md).

**Delegated scopes do not replace operator roles.** Supported roles differ by API: for example, [Conditional Access reads](https://learn.microsoft.com/en-us/graph/api/conditionalaccessroot-list-policies?view=graph-rest-1.0) support Security Reader or Global Reader; [authentication-method policy reads](https://learn.microsoft.com/en-us/graph/api/authenticationmethodspolicy-get?view=graph-rest-1.0) support Global Reader; [directory role-assignment reads](https://learn.microsoft.com/en-us/graph/api/rbacapplication-list-roleassignments?view=graph-rest-1.0) support Directory Readers or Global Reader. These are examples, not a universal role prescription. Have your administrator verify the exact source's existing role/custom-role access. Do not grant Global Administrator merely to eliminate gaps.

### Exchange, Purview and mailbox workflows

- **Exchange configuration Audit:** Graph scopes grant no Exchange cmdlet access. An approved Exchange session and RBAC permitting the selected `Get-*` cmdlets/parameters are required. Verify rights per [Microsoft's cmdlet-permission guidance](https://learn.microsoft.com/en-us/powershell/exchange/find-exchange-cmdlet-permissions?view=exchange-ps); a connected session alone does not prove all selected commands are available.
- **Purview configuration Audit:** DLP/retention read access is separate workload RBAC. The app only reuses an already approved matching Security & Compliance session; it never calls `Connect-IPPSSession`. That service's [connection and RBAC requirements](https://learn.microsoft.com/en-us/powershell/exchange/connect-to-scc-powershell?view=exchange-ps) remain prerequisites. Audit-log reader access alone should not be assumed to cover configuration commands.
- **Session binding:** Graph, Exchange and Purview must match the verified tenant/operator. Exchange/Purview need an active, unprefixed, unambiguous delegated-user REST session with command-origin metadata. Standard collection actions do not reconnect, activate roles or expand scopes. Keep separately established sessions in the same PowerShell process.
- **Terminal Pull Logs:** separate from configuration Audit, its core Graph sources use `AuditLog.Read.All`, `Directory.Read.All` and `IdentityRiskEvent.Read.All`; opted-in Defender hunting also needs `ThreatHunting.Read.All`, supported roles/data access and licensed services. Target scoping does not narrow the token's tenant-wide privileges. Terminal mailbox collection does not fall back to tenant-wide UAL; the legacy investigator below can.
- **Current-only mailbox snapshot:** requires no Graph scopes, but needs existing Exchange access to the four listed commands in the [snapshot guide](terminal/docs/MAILBOX-SNAPSHOT.md). [`Get-InboxRule`](https://learn.microsoft.com/en-us/powershell/module/exchangepowershell/get-inboxrule?view=exchange-ps) is not available under Global Reader or View-Only Organization Management alone. Use administrator-approved scoped cmdlet rights, not a blanket elevation.

### Runtime, licensing and safe failure

Flapjacks requires PowerShell 7.4+; ExchangeOnlineManagement 3.10+ requires PowerShell 7.6+. Microsoft currently documents Security & Compliance PowerShell as unavailable on macOS/Linux; use a supported Windows host for those sources or retain the gaps. Exchange support must match the specific OS/runtime/module matrix, and this project's Debian installer intentionally skips Exchange. See [Microsoft's compatibility matrix](https://learn.microsoft.com/en-us/powershell/exchange/exchange-online-powershell-v2?view=exchange-ps) and the [project setup guide](terminal/docs/PREREQUISITES.md).

Feature licensing is additional to access: Intune needs an active tenant license; Conditional Access/PIM/Identity Protection, Defender and Purview features have source-specific entitlements described in the [permission plan](terminal/Audit/docs/PERMISSIONS.md). A tenant SKU is not proof of an individual user's entitlement. A missing source or HTTP error does not by itself identify whether the cause is licensing, permissions, session state or service availability.

Only request access already approved by your organization. **Stop at new consent requests or Conditional Access blocks.** No consent grant, app registration, password collection, security-setting change or automatic privileged fallback is performed. Denied, disconnected and unsupported sources stay explicit coverage gaps, never a clean security verdict.

## Legacy investigator (preserved)

The original entrypoint and implementation remain unchanged for compatibility and reproducibility. The instructions below describe that **legacy** workflow, which writes a static HTML report and can perform broader tenant-context reads. New operators should use the terminal entrypoint above.


This PowerShell tool collects **read-only metadata** for a target mailbox and produces a local evidence case. It includes a complete synthetic demonstration and executable Exchange, Purview, Entra and optional Defender adapters. It never authenticates, installs modules, retrieves message bodies/attachments, fetches evidence URLs, or remediates a tenant.

**Review-ready fixture build; not live-tenant validated or a complete forensic acquisition.** Non-interactive user sign-ins have a separately labeled, opt-in Graph beta collector; its preview contract can change and is not a production support guarantee. ## Run the synthetic demonstration

PowerShell **7.4+** is required (not Windows PowerShell 5.1). Native tests were run with Microsoft's portable **7.6.9**, macOS arm64. Python, Node, Pester and Microsoft modules are not needed for fixture mode.

From a shell with PowerShell on your PATH:

```sh
cd m365-bec-investigator
pwsh -NoLogo -NoProfile -File ./Start-BecInvestigation.ps1 -Mode Fixture -TargetUpn alex@contoso.example -NonInteractive
```

The result prints the exact `CasePath` and `report.html` path. Open that local HTML file. It has no JavaScript or remote assets. Fixture time is anchored to `2026-11-11T00:00:00Z`; the default period is the preceding 30 days. All records use synthetic identities, reserved example domains and documentation IPs. The scenario links phishing delivery, a Safe Links event, sign-in activity, a delegate-created rule, Bind/Sync mail-access evidence and post-delivery quarantine. Denied/unavailable/partial sources are deliberately included.

For prompts, omit `-TargetUpn` and `-NonInteractive`. The CLI asks for the target UPN and lookback days (default 30). It never asks for a password. `-StartUtc` and `-EndUtc` accept explicit ISO timestamps with offsets; `-LookbackDays` accepts 1–90. Historical timeline bounds are `[start,end)`; returned boundary records remain in raw JSON. Current snapshots always describe collection time.

## Live use — separate operator authentication

Live collection was **not executed** during development. Obtain authorization for the tenant and target first. Existing Microsoft modules and appropriate read roles must already be present; the tool neither installs them nor grants consent. Use a dedicated approved operator account with MFA, separate from the target. Authenticate in the **same PowerShell process** used to run the script; starting a new process loses those sessions.

The following are operator-run examples, not actions this tool performs:

```powershell
# Existing ExchangeOnlineManagement 3.7.0+ is required for Trace V2.
Import-Module ExchangeOnlineManagement
Connect-ExchangeOnline -UserPrincipalName investigator@your-tenant.example
# If your approved audit workflow uses the compliance session:
Connect-IPPSSession -UserPrincipalName investigator@your-tenant.example

Import-Module Microsoft.Graph.Authentication
# Request only the scopes needed for the sources you are authorized to inspect.
# Tenant consent and role assignment must already be separately approved.
Connect-MgGraph -ContextScope Process -Scopes @(
  'AuditLog.Read.All', 'Directory.Read.All', 'IdentityRiskEvent.Read.All',
  'Policy.Read.ConditionalAccess', 'ThreatHunting.Read.All'
)

./Start-BecInvestigation.ps1 -Mode Live -TargetUpn target@your-tenant.example -LookbackDays 30 -IncludeDefender -IncludeNonInteractivePreview -NonInteractive
```

Omit `-IncludeNonInteractivePreview` if preview APIs are not approved for your environment; the report retains the resulting coverage gap. Microsoft documents beta APIs as subject to change and unsupported for production applications. Omit `-IncludeDefender` and `ThreatHunting.Read.All` if Defender is not authorized/needed. Omit other optional scopes when their source is out of scope; missing access is reported. Microsoft may show an interactive MFA/consent screen in those **separate** connection commands. Do not bypass it or supply a password to this tool. No connection commands are embedded in the implementation.

| Source | Existing privileges/capability to verify |
|---|---|
| Exchange snapshots | Scoped Exchange RBAC for the listed Get-* cmdlets and target. `Get-InboxRule` is not available to Global Reader or View-Only Organization Management alone; use a custom approved role with necessary read cmdlets rather than broad administrator access. |
| Trace V2/details | Exchange role allowing message trace, ExchangeOnlineManagement 3.7.0+, mailbox/trace scope. |
| Purview UAL | View-Only Audit Logs or Audit Logs role (for example approved audit-reader access); audit ingestion and relevant workloads enabled. |
| Entra sign-ins/audits | `AuditLog.Read.All`, supported role such as Reports Reader/Security Reader. Graph sign-in download requires P1/P2. CA policy details additionally require a supported CA read scope/role. |
| Target lookup/OAuth grants | `Directory.Read.All` and a supported directory-reading role; grants are current snapshots, with replication delay. |
| Risks | `IdentityRiskEvent.Read.All`, supported security-reading role and eligible Identity Protection license. |
| Defender | `ThreatHunting.Read.All`, supported role/data access and deployed licensed Defender services for each table. |

Microsoft Graph is currently restricted to the **Global** cloud. Unsupported national-cloud contexts are explicitly unavailable; the tool will not guess an endpoint or forward credentials. See the exact [Microsoft source mapping](docs/SOURCES.md). Permissions listed here are requirements to review, not grants.

## Collection behavior and limits

- Exchange retains current mailbox fields, aliases/type, size/quota/archive, forwarding/retain-copy, hidden rules, FullAccess/SendAs and `GrantSendOnBehalfTo`, folder ACLs, client protocols, mobile statistics and mailbox audit/retention fields. Missing/denied commands fail independently. Folder enumeration is bounded; the default cap is 100 ACL queries. Archive-statistics errors do not establish whether an archive exists; check the mailbox snapshot.
- Trace queries sent and received separately for the target plus verified current SMTP aliases/primary address in at most 10-day windows, `ResultSize=5000`. Full pages continue with the documented last recipient/received-time cursor. Repeated/no-progress/saturated/capped queries remain partial. Detail calls default to 200 unique trace/recipient pairs. Raw duplicates are retained; normalized duplicates merge their references and observed directions.
- Trace requests share a conservative local 90-calls/300-second limiter (Microsoft documents 100/5 minutes). Other clients can still cause throttling. Only 429/503/504 retry, at most twice. `Retry-After` longer than 60 seconds stops with a recorded failure rather than retrying early. Provider-owned internal retries are outside this wrapper's accounting.
- UAL uses one-day windows and a stable `ReturnLargeSet` session per window, `ResultSize=5000`, paging until empty or the 50,000/session cap. It queries tenant-wide pages **without an actor-only UserIds filter**, then exports records matched on named target/actor fields, verified mailbox identifiers and mailbox-qualified rule/folder identity boundaries. Thus delegates/admins can be included. Large tenants can hit the cap; narrower investigations or a separately implemented Management Activity API acquisition may be needed. Non-UPN/legacy identity representations and missing target fields can evade matching; this is explicitly not exhaustive attribution.
- Entra follows same-collection, HTTPS Graph nextLinks with bounded pages. Default `-MaxPages 20` applies to each paged query (1–100 accepted by CLI). Interactive/v1.0 collection stays separate. `-IncludeNonInteractivePreview` adds the documented beta `signInEventTypes/any(t: t eq 'nonInteractiveUser')` filter using the same read scopes; only `/beta/auditLogs/signIns` is allowed, with same-collection continuation. Omitting the switch records that coverage as unavailable. Service-principal and managed-identity sign-ins are outside this user-investigation collector. Tenant-wide OAuth grants and user-specific grants are separate; app-only service-principal assignments are not enumerated.
- Defender uses **Graph `POST /v1.0/security/runHuntingQuery`**, a read-only query operation. It queries fixed metadata columns from UrlClickEvents, EmailEvents, EmailPostDeliveryEvents and account-associated AlertEvidence, one-day windows, capped at 10,000 rows per table/window. Saturation is partial. It does not enumerate every tenant alert or all quarantined mail.

Override caps explicitly with `-MaxPages`, `-MaxDetails` and `-MaxFolders`; higher limits increase work and sensitive local evidence. No unbounded retries. Raw `Pages`, `Windows`, attempts and timestamps document what was requested and what failed. Already fetched generic-pager overflow is retained separately as `OverflowItems`; it is not silently counted as processed timeline data.

## Evidence and interpretation

Every case contains self-contained `report.html`, `timeline.csv/json`, `coverage.csv/json`, `correlations.csv/json`, `correspondents.csv`, `summary.json`, per-source `raw/*.json`, `manifest.json` and `manifest.sha256`. Summary records runtime/module versions, implementation hashes, collection times and fixture hash where applicable. Output is constrained to this project, in a unique case directory; existing output is not overwritten and symlink output paths are refused.

Raw values are **reserialized source objects**, not original HTTP bytes. Hashes detect byte changes after export; they do not authenticate Microsoft records or certify time. No source payload is mutated by normalization. Keep raw evidence local and access-controlled; the tool does not change filesystem permissions or encrypt cases. Do not publish a real case.

HTML encodes all evidence as text; URLs are defanged and not linked. CSV neutralizes formula-leading values including whitespace/control prefixes. Raw JSON retains original metadata strings. Do not render raw email-like fields as HTML. There are no bodies, attachments or email-content APIs in these collectors.

The UTC timeline separates historical events from current snapshots and flags missing timestamps. Exact, case-sensitive opaque IDs support **observed shared-identifier** links, not causation. Session links stay within provider families; IP proximity within 30 minutes is explicitly **inferred** and may reflect NAT/proxies. Link generation is capped and disclosed. There is no compromise score.

MailItemsAccessed **Bind** records retain aggregated item IDs; **Sync** remains folder-level, without invented item timestamps. Neither proves human reading; offline reads are absent. Safe Links is not full browsing history and clicks do not prove credential submission. Missing/default message IDs remain unlinked, and click-to-email correlation requires an actual EmailEvents record. `ActionType`, `IsClickedThrough` and click `ReportId` retain separate meanings.

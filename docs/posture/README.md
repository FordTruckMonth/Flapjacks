# Postures checked and why

Flapjacks reads Microsoft 365 configuration for an authorized operator and compares selected stored settings with documented expectations. The app does not change tenant settings. **The 134-item workbook is still in progress.** A source read, a report row, and a fully assessed workbook item are different things.

## Choose the collection profile

| Menu action | Planned sources | Report rows | What it covers |
|---|---:|---:|---|
| **A — Audit** | 46 | 5 | Organization configuration inventory plus the five pilot checks below. |
| **W — Extended workbook posture** | 55 | 80 | The same five checks plus identity registration/account state, Exchange, collaboration, and stored mail-policy comparisons. The terminal selects **Microsoft Standard** for mail comparisons. |
| **L — Pull Logs** | Separate mailbox workflow | Not a posture profile | Historical activity for explicitly selected mailboxes and dates. It does not expand the posture-check count. |

These are planned source/check counts, not counts of successful reads, passing controls, or protected users. The existing [mail/workbook crosswalk](../MAIL-BASELINE.md#coverage-accounting) records 41/134 same-setting/predicate mappings for the Standard comparison; that is implementation mapping, not live-verified workbook coverage. The removed fixture reviewer adds no tenant coverage. No full-workbook or compliance score is calculated.

## How to read a result

- **Meets selected setting:** the complete observed values match this check's stated expectation. It does not prove policy assignment or effective protection.
- **Needs action:** an observed value differs; review business exceptions, scope, and policy precedence before deciding on a change.
- **Not assessed:** evidence is unavailable, incomplete, ambiguous, malformed, or lacks a supported expectation. Denied access and empty responses are never passes.
- **N/A:** an explicit, documented applicability decision for checks supporting that override; never inferred from missing evidence.

Read each source's `Status` **and** `Reason` in `coverage.csv`. `Collected` describes a completed read, not secure configuration. Native Teams and SharePoint/OneDrive snapshot adapters have no verified live collector: their `NotConnected` status cannot be fixed by another sign-in. The separate Graph SharePoint settings read can succeed with its existing approved permissions.

## Standard audit: five checks

Mailbox auditing helps investigations; rejecting Direct Send reduces one anonymous accepted-domain sending path; disabling organization-default SMTP AUTH reduces available submission paths; restricting default-user app creation limits unmanaged application registration; common-attachment filtering adds a file-type defense. Each setting has narrower evidence limits than these broader goals.

| Check / evidence | Expected stored setting | Why it is reviewed |
|---|---|---|
| `EXO-AUDIT` — Organization mailbox auditing switch. Source: `exchange-organization`; field: `AuditDisabled`. | AuditDisabled = false. | The organization-level mailbox auditing disable switch should be off for this selected baseline. |
| `EXO-DIRECT-SEND` — Reject Direct Send organization switch. Source: `exchange-organization`; field: `RejectDirectSend`. | RejectDirectSend = true. | This selected baseline rejects Direct Send; confirm approved device and application mail flows before any configuration change. |
| `EXO-SMTP-AUTH` — Organization SMTP AUTH default. Source: `exchange-transport`; field: `SmtpClientAuthenticationDisabled`. | SmtpClientAuthenticationDisabled = true. | This selected baseline disables SMTP AUTH at the organization default. |
| `ENTRA-APP-REG` — Default users application registration. Source: `authorization-policy`; field: `defaultUserRolePermissions.allowedToCreateApps`. | defaultUserRolePermissions.allowedToCreateApps = false. | This selected baseline restricts application creation by the default user role; use an approved delegated application-management process. |
| `EOP-FILE-FILTER` — Common attachment filter in returned malware policies. Source: `exchange-malware-policies`; field: `EnableFileFilter`. | EnableFileFilter = true. | This selected baseline enables the common attachment filter in every returned malware policy. |

The organization auditing and SMTP AUTH defaults do not resolve mailbox overrides. Direct Send is not a general anti-spoofing verdict. Default-user app registration is a project-selected restrictive baseline, not a universal Microsoft mandate. The attachment-filter switch does not assess the file-type list or recipient targeting. ## Save and review

After A or W, choose **P**, provide a new directory beneath an existing private local folder, and wait for the save confirmation. The bundle includes `Posture-Report.pdf`, `Posture-Report.xlsx`, `Posture-Report.csv`, per-check details, `coverage.csv`, and supporting JSON evidence.
